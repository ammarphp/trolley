# Research workspace

This directory separates an authored AI-safety argument from evidence about the real world and from evidence about the implementation. Draft content is not production-approved content.

- `philosophy/dossiers.md`: inspected primary sources, conceptual distinctions, and adaptation constraints.
- `proposals/philosophy.json`: a source/claim proposal for coordinator review; it does not edit the shared registry.
- `methods/evidence-and-evaluation.md`: evidence layers, artifact evaluation, observational limits, and the disabled formal-study profile.
- `content/candidate-inventory.json`: 154 proposed semantic candidates. The count is an authoring inventory, not a release certification or 154 implemented nodes.
- `fixtures-spec.json`: sixteen reviewable semantic test specifications. These are independent of an implementation language or runtime contract.
- `../docs/privacy/v2-collection-design.md`: consent, compatibility, aggregate, withdrawal, and operational requirements for the proposed v2 service. It is not a statement that v2 is already deployed.

The source brief and addendum remain unchanged in the handoff folder. Local source books must stay outside the public repository. Neither a passing schema test nor a link to a paper establishes narrative approval, empirical calibration, or an educational effect.

## Content promotion

The review sequence is proposed → sourced → modeled → narrative-reviewed → technically validated → playtested → approved. Each promotion names a reviewer, evidence artifact, and content revision. Authors may self-check their own work, but that does not replace independent approval. A node with pending evidence can remain a development fixture when visibly labeled; it cannot carry an unverified real-world claim into production.

Every node needs a meaningful two-option distinction, a coherent decision-maker and authority scope, observable consequences, uncertainty available to that decision-maker, and an explicit account of what is invented. Names, casualty counts, or costumes alone do not create a new semantic node.
